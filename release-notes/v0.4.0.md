# Release v0.4.0

<p align="center">
  <img src="https://github.com/kopecmaciej/vi-sql/blob/master/assets/logo.svg"/>
</p>

Connections move out of `config.yaml` into a dedicated XDG state file, plus a handful of fixes.

## Breaking

- **Connections stored in a state file** — the connection list and `currentConnection` now live in a dedicated state file resolved via the XDG base-directory spec (`$XDG_STATE_HOME/vi-sql/state.yaml`, e.g. `~/.local/state/vi-sql/state.yaml` on Linux by default; different on macOS/Windows). Run `vi-sql --paths` to see where it resolves on your system. This keeps `config.yaml` dotfiles-friendly. Existing connections are migrated automatically the first time you run this version. With `--config <path>`, the state file sits next to that file. ([#81](https://github.com/kopecmaciej/vi-sql/pull/81))

## Fixes

- **GaussDB M-mode compatibility** — assorted fixes for connecting to GaussDB in M-mode. (by @AndrewDi, [#73](https://github.com/kopecmaciej/vi-sql/pull/73))
- **INSERT template formatting** — the comma is now placed before the `REQUIRED` comment in generated INSERT templates. ([30a21b1](https://github.com/kopecmaciej/vi-sql/commit/30a21b1))
- **Ctrl+R keeps the active filter** — refreshing the schema tree re-applies the active filter string to the updated tree immediately. ([#82](https://github.com/kopecmaciej/vi-sql/issues/82))
- **Ctrl+R expand icon** — schema nodes keep their open-node icon after a refresh, matching the initial render.
