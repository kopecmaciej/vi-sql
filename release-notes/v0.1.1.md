# Release v0.1.1

Bug fixes, a SQL Server compatibility improvement, and an in-app update action.

## Features

- **Auto-update from the actions modal** — a new *Update vi-sql* entry in the actions modal downloads and replaces the running binary in one step, with a confirmation prompt before applying. ([#45](https://github.com/kopecmaciej/vi-sql/pull/45))

## Fixes

- **Corrupted output when cell values contain tview format tags** — values like `[red]` or `[::b]` were parsed as tview colour/style tags, producing invalid/midding values in the results grid, peek viewer, and results bar. User values are now escaped before being passed to tview format strings. ([#42](https://github.com/kopecmaciej/vi-sql/issues/42))
- **ORDER BY lost case on quoted identifiers** — column names in `ORDER BY` are now quoted, preserving mixed-case identifiers across all backends. ([#36](https://github.com/kopecmaciej/vi-sql/issues/36))
- **Help page missing `select` action and off-centre footer** — the help page now lists the `select` binding and the footer is properly centred.
- **Ctrl+H triggered Backspace in tmux** — switched to a patched tcell fork that correctly distinguishes `Ctrl+H` from `Backspace` in tmux sessions.

## SQL Server

- Schema and table metadata queries no longer depend on `STRING_AGG` (SQL Server 2017+). The driver now uses `STUFF`/`FOR XML` subqueries and groups results in Go, restoring compatibility with SQL Server 2016. ([#38](https://github.com/kopecmaciej/vi-sql/pull/38))
